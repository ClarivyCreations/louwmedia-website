# Louwmedia website

Astro 7 + EmDash 1.5 (server-rendered). Branch `astro-emdash`; the old static site is in `legacy/`.

## Flow
Design every page in Doop first (canvas "Louwmedia", v4rbrJ43XY: brand book, design system, section library "Secties", page designs on "Pagina's"), get Max's approval, then build it here directly. New sections from Doop become new block types; existing ones keep working.

## Run
- `npm run dev` → http://localhost:4321, admin at /_emdash/admin (local dev bypass is printed in the terminal).
- Schema and sample content: `seed/seed.json`. Apply changes with `npx emdash seed seed/seed.json --on-conflict=update`.
- Local media for the seed lives in `seed/media/` (referenced as `"$media": {"file": "media/..."}`).

## Hosting
- None (Max 2026-11-23): the Cloudflare staging is gone and the site runs locally only (`npm run dev`: Node, data.db, uploads/). The repo goes to the client as the design source: he builds his own site with Claude Code and takes the design over from here.
- data.db and uploads/ are not in git. `seed/seed.json` + `seed/media/` hold the full site (schema, all content, all 37 media files; regenerated from data.db on 2026-11-23), so `npx emdash seed seed/seed.json` on a fresh checkout gives the same site with every image. After content changes, regenerate it: `npx emdash export-seed --with-content=all`, then turn the media references into `{"$media": {"file": "media/<name>"}}` and copy the files from uploads/ to seed/media/. `npm run build` + `npm start` gives a standalone Node server if it ever needs hosting.

## Content model
- `pages`: title + `content` (blocks). `/` renders slug `home`, every other page renders at `/{slug}`.
- `services` (mega menu Diensten, home cards via card_title + card_text, page at `/diensten/{slug}` via src/pages/diensten/[slug].astro): title, summary, menu_note, image, position, content (the service page's own blocks, same set as pages).
- `cases` (mega menu Werk, lm_cases, page `/werk/{slug}` via src/pages/werk/[slug].astro, S20a): **title = the client name** (Max: recognisable in the CMS and in the url; two cases for one client: "Klant – onderwerp"), `headline` = the creative title on the page (*accent*; empty = the client name), intro, deliverables ("Gemaakt"), kind, year, cover (main photo, always), optional `video` (replaces the photo at the top; muted loop, a click plays it with sound in place), review_quote/name/role/image (styled like the FAQ column), `content` = media rows (`lm_media`). `client` is no longer used. Page: full-bleed photo/video with the header over it → headline, facts (Klant, Soort, Gemaakt, Jaar) and intro + review → media rows → next case (one big row, its photo only on hover) → footer. Lists show the client name with the headline as second line. The seeded cases still have placeholder titles "Klantnaam · …"; only `pitstraat` is filled as an example.
- `reels` (home reels carousel, later /werk): title, meta, video (vertical file), poster, position. A repeater cannot hold files, hence a collection.
- `reviews` (the lm_quote section, Max 2026-11-21: one list, the same reviews everywhere): title (client name), quote, role, image, position.
- `gegevens` "Bedrijfsgegevens" (Max 2026-11-21: one place for Louwmedia's own details): a single item `louwmedia` with name, email, phone (+ note), street, postal code, city, area, KvK, Instagram/TikTok/LinkedIn/YouTube links and the default sharing image. Read through src/utils/company.ts (`getCompany`, `isReal`, `mailHref`, `telHref`) by the footer, the contact hero, the FAQ contact lines, the og:image fallback and the home page's ProfessionalService JSON-LD. A [placeholder] value shows as text but never becomes a link or structured data; an empty social is left out everywhere. The old `social` menu is no longer used.
- Menus: `primary` (item class `mega-werk` / `mega-diensten` opens a mega menu, `button` = Contact button), `footer`, `social`.

## Design
- Tokens in `src/styles/tokens.css`, names match the Doop tokens.
- Page edge (Max, 2026-11-20): sections are boxed (`.container`, max `--container` + `--gutter`; the container is 1360 up to a 1440 screen and grows to 1440 at 1680+). Things outside a container (header bar, hero text) use `--edge` = max(gutter, (100% − container) / 2) in their padding, so on large screens they move in with the boxed content (1920: 240px; ≤1440: 40px). Full-bleed media (hero photos, video) still run to the screen edge.
- Type scale (Max: one proper scale, subtler on mobile): label 11/12, text-s 13/14, text-m 16/17, text-l 18/22, h5 17/20, h4 20/26, h3 24/40, h2 30/64, h1 40/96, display 48/136 (mobile 390 / desktop 1440), fluid in between with clamp(). Never write a pixel font size in a block; use these tokens. In Doop the mobile values are the token theme "mobile" (`data-doop-theme="mobile"` on a mobile frame's html).
- Paragraph text has three sizes (Max, 2026-11-20), tokens `--text-l/-m/-s`, classes `.text-l/.text-m/.text-s`. L: the one lead line beside a big heading (hero intro, statement, the closers lm_cta and lm_edit). M (default, body): reading text, so intros beside an h2, card text, FAQ answers, nav links. S: short supporting lines under a small title (steps, deliverable cards, menu rows) and meta (client, year, role, captions, logo label). Buttons and the EditorTimeline UI keep their own sizes.
- Styling a class passed to Headline.astro (or any child component) needs `:global(...)`: Astro's scoping does not reach the child's element.
- Overriding a global class (`.slant`, `.container`, `.text-link`…) from a component: put a scoped parent in front (`.hs__media :global(.hs__photo)`), never a bare `:global(.x)`. A bare one has the same specificity as the global rule, and the production build loads the CSS in a different order than dev (2026-11-22: the split hero's photos were 0px high in the production build only).
- Fonts: Inter 600 + 900 italic (display), Hanken Grotesk (body), Geist Mono (labels), Permanent Marker (scribbles).
- Red #FF2E17 is an accent, never a full section. Exception Max chose: the second stacking service card is red (gradient). REC dot = `--spacing-rec` (6px).
- Slanted photos: `.slant` (skewX 12.7°, radius 10px).
- Service pages (Max): hero split → klanten (logo row) → statement → wat je krijgt → klantcases (black, filtered by kind) → hoe het werkt → FAQ with the review and contact column → afsluiter `lm_edit` "Van idee naar *edit*." (the editor timeline). All three are filled (Bedrijfsvideo and Fotografie on 2026-11-20 with the same blocks; quotes, client names and case details are still placeholders). Avoid stills from the reels for photos: most have burned-in subtitles; subtitle-free frames are the bv-*, fo-* and project-* photos in seed/media.
- Hover on text and links: three types only (Max, 2026-11-20). 1) Button (`Button.astro`): letter roll + arrow swap. 2) Text with a line (`.text-link`): the line grows to full width, also when its parent link is hovered. 3) Text without a line (`<Roll text="…" />`): the same letter roll as the button. No colour, opacity, weight or italic change on hover. Timing: `--roll-duration` / `--roll-stagger` in tokens.css. Photos may still zoom slightly on hover.

## Shared small parts (Max: reuse the recurring bits, not only the sections)
Never redraw these inline; use the component (styles in global.css so a parent's hover reaches them):
- `Arrow.astro`: the brand arrow (text links, buttons, anywhere).
- `ArrowSquare.astro` (`.asq`): the Button's arrow square with the arrow swap on hover of the surrounding link/button. `tone="solid"` red gradient (Button), `tone="outline"` line that turns red on hover (Diensten menu rows, keuzehulp rows, next case); `size="l"` = 56px.
- `PlayButton.astro` (`.pbtn`): round glass play button, shows pause while an ancestor has `.is-playing`; size via `--play` (showreel hero, case video).
- `TextLink.astro`: text + arrow with the growing line (`.text-link`); without href a span inside a bigger link.
- `Tag.astro`: label with the REC dot. `SlantPhoto.astro`: the slanted photo (`.slant`), size via the class you pass.
- `Review.astro`: score (optional, Google G), quote with marker, slanted avatar + name/role (FAQ column, case pages).
- `Button.astro`, `Roll.astro` (letter roll), `Headline.astro`, `CircledHeadline.astro`, `EditorTimeline.astro`.
A class passed to one of these sits on the child's root, so a block styles it with `:global(.my-class)`.
In Doop the same parts are components with the code path filled in (Button, TextLink, Tag, SlantPhoto, EditorTimeline, ArrowSquare, PlayButton, Review). Still drawn inline in some blocks and worth extracting next: the viewfinder corners (Doop VideoFrame: statement + home hero), StatCard/ReelCard (wat je krijgt), StepRow (werkwijze), CaseThumb (Werk menu).
Tokens: colours, radius, fonts and the type scale match Doop 1:1. Doop's `--spacing-*` scale is not used in code (sections use `--section-space`, `--gutter`, `--edge`); Doop `--container-site` = code `--container`.
Before adding a new small element, check this list and the Doop components first.

## Motion (GSAP, src/scripts/motion.ts and header.ts)
- Preloader (first page of a visit only, sessionStorage `lm-seen`): logo letters stagger in on white, then the video hero's strip → card → full screen intro. Every other page view still gets the short hero entrance (`introSimple`: header drops in, headline lines rise, text fades up, slanted photos drift in a little from the left while fading in, slowly) and all scroll reveals (Max, 2026-11-20).
- Page transition (Max, 2026-11-20, after Osmo's diagonal transition): native cross-document View Transitions in global.css (`@view-transition`). The old page dims, the new one wipes in from the top with a leading edge on the brand slant (12.7°); the header is its own group (`site-header`) and crossfades. Pages stay normal page loads, so no script needs re-initialising. `pagereveal` (inline script in Base.astro) hands the transition to motion.ts, which starts the hero entrance once the wipe is done. Firefox and reduced motion: a plain navigation.
- `data-reveal="lines"` splits a heading into lines that rise on scroll; `data-reveal` fades up; `data-reveal="photo"` clip reveal.
- Scribbles draw themselves (Max, 2026-11-20, after Extrafazant's buttons): a word with `data-scribble="line"` (the `_marker_`) or `"circle"` (Cta accent) holds an SVG with the red marker texture and a thick pen route as a mask (`src/utils/scribbles.ts`, `src/scripts/scribbles.ts`). It is drawn once its heading's lines are up (or when scrolled into view), and every hover draws the next of 3 variants. To add one: put the PNG in, add it to `tools/build-scribbles.py`, rerun, copy the JSON into scribbles.ts.
- Everything respects `prefers-reduced-motion`.
